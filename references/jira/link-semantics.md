# Jira link semantics

Known instance link families include blocking, release blocking, duplicate, generated, related, defect, release membership, and cloning relationships.

## Use links only when they change understanding

- `blocks` / `is blocked by`: execution dependency with direction.
- release-blocking relationship: affects release readiness, not necessarily implementation start.
- `duplicates` / `is duplicated by`: avoid parallel delivery of the same outcome.
- `generated` / `is generated by`: preserve provenance between discovery and resulting work.
- `relates to`: informational relationship without ordering.
- defect relationship: connects a discovered defect to affected work.
- clone relationship: provenance, not automatically a dependency.

## Creation rules

- Prefer an explicit directional blocker when work cannot complete until another issue does.
- Use `related` when context matters but neither issue blocks the other.
- Do not create every possible relationship; noisy graphs hide actual dependencies.
- Do not create a blocker merely because one task's key is numerically earlier.
- Verify the live link type name and inward/outward direction before writing.
